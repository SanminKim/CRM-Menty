# CRM Менти

CRM школы менторства аналитиков 1С: ведёт каждого человека от заявки до оффера и испытательного срока, считает платежи студентов и долю партнёра-блогера. Работает на своём сервере, вход по логину и паролю.

## Что умеет

- **Сегодня.** Что нужно сделать: шаги с датой, платежи с подходящим сроком, встречи на неделе, студенты без следующего шага.
- **Календарь.** Встречи со студентами и занятия потоков, отметки «состоялась / не состоялась», собеседования из откликов.
- **Воронка.** 10 этапов от новой заявки до прохождения испытательного срока, карточки перетаскиваются.
- **Карточка студента.** Контакты, следующий шаг, прогресс по модулям, платежи и рассрочка, отклики, встречи, заметки, история этапов и журнал изменений по деньгам.
- **Потоки.** Программа из модулей, прогресс каждого студента, массовые действия.
- **Аналитика и финансы.** Воронка, конверсии, выручка по месяцам, сравнение источников и потоков.
- **Партнёры.** Доля блогера фиксируется в заявке, начисления считаются по фактическим оплатам, выплаты учитываются. Партнёр видит отчёт без контактов студентов.
- **Заявки с сайта.** Форма на сайте сама создаёт заявку с шагом «Связаться».
- **Роли.** Администратор видит всё. Ментор видит только своих студентов, без финансов школы и партнёров. Партнёр видит только отчёт по своему трафику.

## Как устроено

```
web/index.html     вся страница CRM: разметка, стили и скрипт в одном файле, без сборки
web/server.js      слой данных страницы: ходит в API сервера, держит записи в памяти, опрашивает изменения
backend/           сервер на Django: хранение записей, права, вход, заявки с сайта, загрузка копии
  models.py        Doc (запись), Account (роль пользователя), State (счётчик ревизий), Tombstone, LeadLog
  store.py         чтение и запись с проверкой прав — все правила доступа здесь
  api.py           JSON API для страницы
  leads.py         приём заявок с сайта
  backup.py        загрузка резервной копии
  views.py         страница CRM, вход, смена пароля
  tests.py         тесты сервера
e2e/run.py         сквозная проверка в браузере на настоящем сервере
docker/            Caddy (HTTPS), ночные копии базы, запуск контейнера
web/dev/mock.js    подмена данных для просмотра страницы без сервера
```

Страница работает с данными как с документами: студент со всеми платежами, откликами и заметками — одна запись. Сервер хранит записи как есть (таблица `Doc`), проверяет права на каждую запись и отдаёт изменения по номеру ревизии. Новая возможность обычно делается только в `web/index.html`; сервер меняется, когда появляется новая коллекция или новое правило доступа.

Стек: Python 3.12, Django 5.2, PostgreSQL 16, Docker, Caddy.

## Запуск на своём компьютере

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py create_admin admin --name "Имя Фамилия"   # спросит пароль
python manage.py runserver
```

Откройте http://127.0.0.1:8000 и войдите. Локально используется SQLite. Примерные данные загружаются кнопкой на пустой странице или в настройках.

## Установка на сервер

Нужен сервер с Ubuntu 22.04 или новее, от 1 ГБ памяти, и домен, у которого A-запись указывает на IP сервера. Персональные данные граждан России по закону хранятся на серверах в России.

```bash
curl -fsSL https://get.docker.com | sh                 # Docker
git clone https://github.com/SanminKim/CRM-Menty.git /opt/crm-menty
cd /opt/crm-menty
cp .env.example .env
nano .env                                              # домен, ключи и пароли: подсказки внутри файла
docker compose up -d --build
docker compose exec web python manage.py create_admin admin --name "Имя Фамилия"
```

Через минуту CRM откроется на `https://ваш-домен`. Сертификат HTTPS выпускается сам.

В `.env` обязательно замените `SECRET_KEY`, `POSTGRES_PASSWORD` и `LEAD_WEBHOOK_TOKEN` на случайные значения. С ключом из примера сервер не запустится, а приём заявок останется выключенным.

### Обновление

```bash
cd /opt/crm-menty && git pull --ff-only && docker compose up -d --build
```

То же делает GitHub сам после каждого изменения в `main` (`.github/workflows/deploy.yml`), если в настройках репозитория заданы секреты `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_PATH`.

### Перенос данных из версии в Claude

1. На странице в Claude: Настройки → Резервная копия → «Скачать резервную копию».
2. На сервере: Настройки → Резервная копия → «Загрузить копию».

Переносятся студенты со всей историей, потоки, команда, партнёры, выплаты и встречи. Примерные записи пропускаются. Повторная загрузка ничего не дублирует.

### Пользователи

Настройки → Доступ. Ментора сначала добавляют в «Команду», затем выдают ему логин и пароль и выбирают, кто он в команде: по этой связи он видит своих студентов. Партнёру выбирают запись партнёра: он увидит отчёт по ней. Пароль человек меняет сам в настройках.

Забытый пароль администратора сбрасывается на сервере: `docker compose exec web python manage.py create_admin admin`.

### Заявки с сайта

```
POST https://ваш-домен/api/leads/        заголовок X-Token: <LEAD_WEBHOOK_TOKEN из .env>
```

Принимает form-data или JSON. Поля: `name`, `phone`, `email`, `telegram`, `city`, `utm_source`, `utm_campaign`, `promo`, `consent`, `comment`. Если форма не умеет слать заголовки, токен можно передать в адресе: `/api/leads/?token=…`.

- Заявка привязывается к партнёру по промокоду, а если его нет — по `utm_source`.
- Повторная заявка с тем же телефоном, почтой или Telegram не создаёт дубль, а добавляет заметку в карточку.
- Новая заявка никому из менторов не назначена: её видит администратор и назначает ментора.
- Не больше 30 заявок в минуту.

### Резервные копии

Контейнер `backup` раз в сутки сохраняет базу в папку `backups` на сервере и хранит 14 дней. Копируйте эту папку за пределы сервера: копия на том же диске не спасёт, если пропадёт сервер.

Восстановление:

```bash
gunzip -c backups/crm_2026-10-01_0300.sql.gz | docker compose exec -T db psql -U crm crm
docker compose restart web
```

После восстановления попросите всех обновить страницу.

## Разработка

```bash
python manage.py test backend                 # тесты сервера
python manage.py makemigrations --check --dry-run
node --check web/server.js
python e2e/run.py                             # сквозная проверка в браузере (нужен playwright)
```

Каждый push проверяется в GitHub (`.github/workflows/tests.yml`). Правила проекта и порядок работы с Claude Code — в `CLAUDE.md`, набор агентов и навыков — в `.claude/`.
