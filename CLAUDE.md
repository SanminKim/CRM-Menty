# CRM Менти

CRM школы менторства аналитиков 1С: путь человека от заявки до оффера, платежи студентов, расчёт с партнёром-блогером. Интерфейс и тексты — на русском.

## Две версии

- **`web/index.html` — рабочая версия.** Одна страница, опубликованная как артефакт в Claude, данные лежат во встроенной базе артефакта. Все новые функции делаются здесь. Подробности — `web/README.md`.
- **Django-версия в корне — заморожена.** Запасной путь для переезда на свой сервер. В неё вносятся только две вещи: исправления ошибок и поддержка импорта резервной копии (`crm/backup.py`). Не дублируйте в ней новые функции веб-версии, пока владелец не решит переезжать.

Ссылка на опубликованную страницу хранится в проекте Claude «CRM Менти», а не в репозитории. Не добавляйте её в код и документацию: репозиторий публичный.

## Команды

```bash
pip install -r requirements.txt
python manage.py test                      # тесты Django-версии
python manage.py makemigrations --check --dry-run
node -e "new Function(require('fs').readFileSync('web/index.html','utf8').split('<script>')[1].split('</script>')[0])"   # синтаксис веб-версии
```

Веб-версию локально проверяют в браузере с `web/dev/mock.js` (подмена `window.claude`, данные в `localStorage`).

## Как ведём разработку

Порядок работы взят из ECC (см. `.claude/ECC.md`) и подогнан под проект:

1. **План.** Для задачи крупнее мелкой правки сначала план: что меняем, какие файлы, риски, как проверим. Агент `planner` или команда `/plan`. План согласуется с владельцем до начала работы.
2. **Тест до кода**, где это возможно. Django: тест в `crm/tests.py`, который сначала падает. Веб-версия: сценарий проверки в браузере через `web/dev/mock.js`.
3. **Реализация** минимальным изменением. Никаких функций «на вырост».
4. **Ревью** перед коммитом: `code-reviewer` для любого изменения, `django-reviewer` или `python-reviewer` для Python, `security-reviewer` для всего, что касается прав доступа, персональных данных, платежей и приёма заявок, `database-reviewer` для моделей и миграций.
5. **Проверка.** Тесты проходят, миграции согласованы, веб-страница открыта и сценарий пройден руками или скриптом. Навык `verification-loop`.
6. **Коммит и публикация.** Коммит в `main`, push, затем переопубликовать артефакт, если менялся `web/index.html`.

## Правила проекта

Если навык или агент из ECC расходится с этим разделом, действует этот раздел.

- **Тесты Django — встроенный раннер** (`manage.py test`, `django.test.TestCase`). Не переводите проект на pytest, factory_boy или DRF без запроса владельца.
- **Веб-версия — один файл без сборки.** Не добавляйте React, сборщики и внешние библиотеки. Правило «много маленьких файлов» к ней не применяется.
- **Данные студентов не попадают в репозиторий**: ни в код, ни в тесты, ни в примеры. Для примеров — вымышленные имена.
- **Секреты только через переменные окружения** (`.env`, в git не коммитится).
- **Права доступа веб-версии** описаны в `web/README.md`. Партнёр (уровень `view`) читает только коллекцию `reports`. Любое изменение правил проверяется чтением базы с пониженным уровнем доступа.
- **Формат резервной копии** (`crm-menti-backup`) — контракт между версиями. При изменении структуры записей в веб-версии обновите `crm/backup.py`, тесты импорта и поднимите `version`.
- **Сообщения коммитов — на русском**, первая строка говорит, что изменилось для пользователя.
- **Правки студента в веб-версии — только через `patchStudent`.** База заменяет массивы (платежи, отклики, заметки, история) целиком, поэтому патч считается от свежей записи, а «Отменить» откатывает только свой элемент.
- **Всё, что попадает в разметку из базы, проходит через `esc()`**, включая идентификаторы и числа в атрибутах.
- **Этапы воронки** заданы в двух местах: `STAGES` в `web/index.html` и `Stage` в `crm/models.py`. Меняются вместе.
