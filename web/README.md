# Веб-версия CRM (страница в Claude)

`index.html` — вся CRM одной страницей. Она опубликована как артефакт в Claude и хранит данные во встроенной базе артефакта, сервер не нужен.

Этой версией можно пользоваться уже сейчас. Django-версия в корне репозитория — для переезда на свой сервер, когда поток вырастет.

## Как устроено

- Разметка, стили и скрипт лежат в одном файле, без сборки.
- Данные читаются и пишутся через `claude.use("db")`. Коллекции: `students`, `cohorts`, `partners`, `payouts`, `team`, `reports`, `meetings`, документ `config/main`.
- Платежи, отклики, заметки и история этапов хранятся внутри документа студента.
- Массивы внутри студента база заменяет целиком, поэтому все правки идут через `patchStudent`: патч считается от свежей записи в очереди записи, а «Отменить» откатывает только свой элемент.
- Прогресс студента (`progress`) — объект, а не массив: база сливает его по ключам, поэтому отметка одного модуля не затирает остальные. Снятая отметка записывается как `null`.
- Модули потока редактируются текстом, по одному в строке. Совпавшие по названию сохраняют id; новое название на месте исчезнувшего считается переименованием (`mergeModules`).
- В документе `config/main` хранится `lastBackupAt` — время последней резервной копии. По нему экран «Сегодня» напоминает о копии старше 7 дней.
- Отчёт для партнёра — отдельный документ в `reports`. В нём только цифры и сокращённые имена, без контактов. После первой публикации он обновляется сам: через пару секунд после каждой успешной записи страница пересчитывает отчёт и записывает его, если цифры изменились (`refreshReports`).
- Встречи календаря — отдельная коллекция `meetings`: `{title, date, time, kind, status, duration, studentId, cohortId, mentorId, link, notes}`. Дата и время хранятся строками (`2026-10-05`, `15:30`), без часового пояса. Собеседования в календаре не хранятся: они берутся из откликов студентов (`apps[].interview`). Состоявшаяся встреча со студентом добавляет заметку с `kind: "meet"`.
- Удаление студента обратимо: записи ставится `deletedAt`, она пропадает из списков, расчётов и отчётов и лежит в «Настройки → Корзина» (`S.trash`). Насовсем запись удаляется только оттуда, вместе с личными встречами.
- Журнал изменений по деньгам — массив `log` в документе студента: `{id, at, by, text}`. В него пишутся добавление, изменение, удаление и оплата платежа, создание рассрочки и смена стоимости. Хранятся последние 200 записей.
- Форма студента записывает только те поля, которые изменили в форме, чтобы не затирать чужие правки соседних полей.

## Резервная копия

Настройки → Резервная копия скачивает всю базу одним JSON-файлом:

```json
{"format": "crm-menti-backup", "version": 4, "exportedAt": "…",
 "data": {"students": [], "cohorts": [], "partners": [], "payouts": [], "team": [], "reports": [], "meetings": []}}
```

Версия 2 добавила студенту поле `next` — следующий шаг: `{"text": "Созвон", "date": "2026-10-05"}` или `null`. Версия 3 добавила программу потока `modules` — список `{"id": "m1", "title": "Введение"}` — и прогресс студента `progress` — объект «id модуля → дата отметки» (`null`, если отметку сняли). Версия 4 добавила раздел `meetings`, пометку `deletedAt` у студентов из корзины и журнал `log`. Импорт принимает версии 1–4: студенты из корзины не переносятся, записи журнала становятся заметками «Деньги: …». Встречи, перенесённые раньше, повторный импорт не обновляет, даже с заменой студентов.

Этот файл принимает Django-версия, см. раздел «Переезд с веб-версии» в корневом README. При изменении структуры записей поднимайте `version` и обновляйте `crm/backup.py`.

## Права доступа

Страница публикуется с такими возможностями:

```json
{
  "db": {"rules": [
    {"path": "", "read": "interact", "write": "interact"},
    {"path": "reports", "read": "view", "write": "interact"}
  ]},
  "user": {"scopes": ["profile"]},
  "downloads": true
}
```

- Редакторы и участники с правом изменения читают и пишут всё.
- Зрители (блогер) читают только `reports`. Встречи, как и студенты, им недоступны: коллекция `meetings` подпадает под общее правило.

## Как обновить опубликованную страницу

Правки в этом файле сами в Claude не попадают. После изменения попросите Claude в чате проекта подтянуть код из репозитория и переопубликовать страницу. Данные в базе при этом сохраняются.

## Локальный просмотр

`dev/mock.js` подменяет `window.claude` и хранит данные в `localStorage` браузера. Чтобы открыть страницу локально, оберните `index.html` в обычный HTML-документ и подключите `dev/mock.js` в `<head>` перед содержимым страницы. Параметр `?role=partner` показывает страницу глазами блогера.
