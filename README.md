# CRM менторства

CRM для школы-менторства аналитиков 1С: ведёт каждого человека от заявки до оффера и прохождения испытательного срока, считает платежи студентов и долю партнёра-блогера.

В репозитории две версии:

- **Веб-версия** в папке [`web/`](web/) — одна страница, опубликованная в Claude, данные хранятся там же. Ей пользуемся сейчас.
- **Django-версия** в корне — для своего сервера. Всё, что ниже, относится к ней.

## Что умеет

- **Воронка (канбан).** 10 этапов: Новая заявка → Связались → Созвон → Ждём оплату → Обучается → Итоговый проект → Поиск работы → Оффер → Прошёл испытательный, плюс «Отказ / выбыл». Карточки перетаскиваются мышкой, каждая смена этапа пишется в историю.
- **Карточка студента.** Контакты, поток, ментор, источник, заметки, история этапов.
- **Платежи.** Разовые платежи и график рассрочки в один клик, просрочки подсвечиваются, остаток по договору считается сам.
- **Трудоустройство.** Отклики, тестовые, собеседования, офферы. Статус «Оффер принят» сам переводит студента на этап «Оффер».
- **Партнёры.** Доля блогера фиксируется в момент привязки студента, начисления считаются по фактическим оплатам, выплаты учитываются, остаток к выплате виден сразу.
- **Отчёт для блогера.** Партнёр входит под своим логином и видит только свой трафик: воронку, оплаты и свою долю. Имена показаны сокращённо («Иван П.»), контакты скрыты.
- **Сводка.** Конверсия в оплату, % трудоустройства, средняя зарплата, дни до оффера, выручка, «застрявшие» студенты, просрочки, собеседования на неделе.
- **Приём заявок с сайта.** Webhook для Tilda или любой формы, автопривязка к партнёру по промокоду или utm_source, защита от дублей.
- **Роли.** Администратор видит всё. Ментор видит только своих студентов, без финансов школы. Партнёр видит только свой отчёт.
- Выгрузка студентов в Excel (CSV), админка для справочников, тёмная тема, мобильная вёрстка.

Стек: Python 3.12, Django 5.2, PostgreSQL 16, Docker, Caddy (автоматический HTTPS).

## Быстрый старт на своём компьютере

Нужен Python 3.11+.

```bash
git clone <ссылка на репозиторий> mentee-crm
cd mentee-crm
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo       # демо-данные: admin / mentor / blogger, пароль demo12345
python manage.py runserver
```

Откройте http://127.0.0.1:8000. Локально используется SQLite, ничего ставить не нужно.

Чтобы начать с чистой базы без демо-данных: `python manage.py createsuperuser` вместо `seed_demo`.

## Пользователи и роли

Всё делается в разделе **Настройки** (это админка Django, `/admin/`):

1. **Ментор:** Пользователи → Добавить → в поле «Группы» выбрать «Менторы».
2. **Второй администратор:** группа «Администраторы».
3. **Блогер:** создать пользователя без групп, затем в «Партнёры» выбрать его в поле «Учётная запись». После входа он сразу попадает в свой отчёт.
4. **Потоки:** «Потоки» → название, даты, базовая цена. Новые заявки с сайта попадают в ближайший активный поток.

## Приём заявок с лендинга

Адрес для webhook:

```
https://ваш-домен/api/leads/?token=<LEAD_WEBHOOK_TOKEN из .env>
```

Принимает form-data или JSON. Поля: `name`, `phone`, `email`, `telegram`, `city`, `utm_source`, `utm_campaign`, `promo`, `consent`.

- **Tilda:** Настройки сайта → Формы → Webhook → вставить адрес. В форму добавить скрытые поля `utm_source`, `utm_campaign` и, при необходимости, поле `promo`.
- **Привязка к партнёру:** по промокоду, если его нет — по `utm_source`. Промокод и utm_source партнёра задаются в его карточке.
- **Повторная заявка** с тем же телефоном или email не создаёт дубль, а добавляет заметку в существующую карточку.

## Размещение на сервере

Подойдёт любой VPS с 1–2 ГБ RAM и Ubuntu 22.04+. Если храните персональные данные граждан РФ, сервер должен быть в России (152-ФЗ), для Казахстана — в Казахстане.

1. Купите домен или поддомен (например, `crm.вашшкола.ru`) и направьте A-запись на IP сервера.
2. На сервере установите Docker: `curl -fsSL https://get.docker.com | sh`
3. Разверните проект:

```bash
git clone <ссылка на репозиторий> /opt/mentee-crm
cd /opt/mentee-crm
cp .env.example .env
nano .env                         # заполнить DOMAIN, SECRET_KEY, пароли, токен
docker compose up -d --build
docker compose exec web python manage.py createsuperuser
```

Через минуту CRM откроется на `https://ваш-домен`. Сертификат HTTPS выпускается автоматически.

### Бэкапы

Контейнер `backup` раз в сутки делает дамп базы в папку `/opt/mentee-crm/backups` и хранит последние 14 дней. Периодически копируйте эту папку за пределы сервера, например в облачное хранилище.

Восстановление из бэкапа:

```bash
gunzip -c backups/crm_2026-10-01_0300.sql.gz | docker compose exec -T db psql -U crm crm
```

## Совместная разработка

Код лежит в GitHub, каждый участник работает в своей ветке.

1. Создайте приватный репозиторий на GitHub и загрузите проект:
   ```bash
   git init && git add . && git commit -m "Первая версия CRM"
   git remote add origin git@github.com:<вы>/mentee-crm.git
   git push -u origin main
   ```
2. Добавьте разработчиков: Settings → Collaborators.
3. Порядок работы:
   ```bash
   git checkout -b feature/название   # новая ветка под задачу
   # ...правки...
   python manage.py makemigrations   # если меняли модели
   python manage.py test             # тесты должны быть зелёными
   git push -u origin feature/название
   ```
   Затем откройте Pull Request, другой участник смотрит изменения и нажимает Merge.
4. **Автоматика:**
   - Тесты запускаются на каждый push и PR (`.github/workflows/tests.yml`).
   - После слияния в `main` код сам выкатывается на сервер (`.github/workflows/deploy.yml`), если в Settings → Secrets заданы `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_PATH`.
   - Рекомендуется защитить ветку `main`: Settings → Branches → Require pull request + Require status checks.

## Где что лежит

```
config/settings.py        настройки (всё переопределяется через .env)
crm/models.py             модели: студенты, этапы, платежи, партнёры, отклики, заметки
crm/services.py           расчёт метрик сводки и отчёта партнёра
crm/permissions.py        роли и права доступа
crm/views.py              страницы и webhook заявок
crm/templates/crm/        HTML-шаблоны
crm/static/crm/           стили и скрипт канбана
crm/tests.py              тесты
crm/management/commands/seed_demo.py   демо-данные
docker/                   Caddy, бэкапы, запуск контейнера
```

**Как добавить или переименовать этап:** отредактируйте `Stage` и `STAGE_GROUPS` в `crm/models.py`, затем выполните `python manage.py makemigrations`.
